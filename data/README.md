# Data

Fully **synthetic** data for Egypt, generated by `scripts/generate_data.py` (seeded, reproducible).
Nothing here comes from a real company.

```bash
uv run python scripts/generate_data.py   # rebuilds data/sales.db in ~15 seconds
```

`data/sales.db` is git-ignored because it can be rebuilt exactly from the seed (default `42`); the
Docker build (Phase 7) runs the generator. A 200-row-per-table preview is committed in `data/sample/`
(CSV) so you can browse the data on GitHub without running anything.

## Schema

```
outlets (300)            sales_weekly (~360k)                 skus (25)
  outlet_id  PK   <----    outlet_id   FK            ---->     sku_id     PK
  outlet_name              sku_id      FK                      brand
  channel                  week_start  (Monday)                flavour
  region                   units                               category
  opened_date              unit_price_egp                      pack_size   e.g. "330ml can"
                           promo_id    FK, nullable            pack_type   can/small/medium/large
promotions (122)  <----    revenue_egp                         price_egp   launch list price
  promo_id   PK            PK = (week_start, outlet_id, sku_id)
  sku_id     FK
  channel    NULL = all channels
  start_week / end_week    week_start of first / last promo week (inclusive)
  discount_pct             10, 15, 20 or 25
```

| Table | Rows | Grain |
|-------|------|-------|
| `outlets` | 300 | one per outlet |
| `skus` | 25 | one per SKU |
| `promotions` | ~120 | one per promotion (SKU, channel scope, weeks, discount) |
| `sales_weekly` | ~360k | one per outlet x SKU x week |

Values: channels are `kiosk`, `supermarket`, `restaurant_cafe`, `hypermarket`; regions are
`Cairo`, `Giza`, `Alexandria`, `Delta`, `Upper Egypt`. Weeks run 2024-01-01 to 2025-12-22.

## What is simulated

Weekly units = outlet scale x SKU popularity x pack/channel affinity x outlet-SKU taste
x **seasonality** (summer peak, stronger in Upper Egypt) x **Ramadan** (real 2024/2025 dates,
bigger in hypermarkets) x yearly **trend** x **promo lift** (discount and a per-SKU price
elasticity), with negative-binomial noise.

## Things to know before analysing it

- **Zero units = stock-out**, not "no demand" (~3% of rows). There is no stock column, so
  stock-outs are not flagged and look like zero sales, as in many real sales extracts.
- **Each outlet only stocks a subset of SKUs.** A missing row means "not stocked", not zero.
  Outlets that opened during the period have no rows before `opened_date`.
- `unit_price_egp` is the price charged that week: list price (two increases, Jul 2024
  +10% and Apr 2025 +8%) minus any promotion discount. `skus.price_egp` is the January 2024 price.
- Promotions respect the policy in `docs/`: 1-3 weeks, at least 4 weeks apart per SKU.
- Simplifications: no post-promotion dip, no cannibalisation between SKUs, no weather.
